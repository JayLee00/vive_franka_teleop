## 4. ★ "hand state 만 외우는 것 같다" — 3단계로 규명

### (1) ablation — 학습된 정책이 무엇을 쓰는가 (`ablation.json`)

`v2_base` 에서 센서군을 하나씩 가리고 rollout:

| 가린 군 | MAE | R² | Δ |
|---|---:|---:|---:|
| (기준) | 337.8 | 0.543 | — |
| **`03_hand_j_pos`** | **567.6** | **−0.056** | **+68.0%** |
| `06_hand_j_kin` | 347.5 | 0.519 | +2.9% |
| `10_hand_paxini_ft` | 348.2 | 0.514 | +3.1% |
| `30_fruit_pos` | 342.0 | 0.531 | +1.3% |

`03_hand_j_pos` **만 남기고 전부 가려도 343.4** — 전 센서(337.8)와 사실상 같다.
과일 방향은 가리면 오히려 좋아진다(노이즈로 작용).

### (2) 선형 프로브 — 정보가 있기는 한가 (`probe.json`)

obs(t) → action(t+0.4s) ridge 회귀, 잔차(= action − 현재 손 자세) 기준 홀드아웃 R²:

| 입력 | 잔차 R² | 손 관절만 대비 |
|---|---:|---:|
| 손 관절만 | 0.6230 | — |
| 전체 obs | 0.6274 | +0.004 |
| 손 + `06_hand_j_kin` | 0.6454 | +0.0225 |
| 손 + `30_fruit_pos` | 0.6324 | +0.0095 |
| 손 + `10_hand_paxini_ft` | 0.6063 | −0.0166 |

**선형 회귀조차 최대 +0.02** 밖에 못 얻는다 → 모델·목적함수 문제가 아니라 정보 부재.
모달리티 dropout 으로 강제해도 `v2_moddrop02` 의 ablation 은 여전히 hand +60.1% /
나머지 ≤1.3% 였다. **없는 정보는 강제해도 못 쓴다.**

### (3) 낙하 구간 프로브 — 정보가 어디에 있나 (`probe_drop.json`, 분석 전용·학습 미사용)

노트가 제외한 낙하 데모 2개에서 같은 프로브:

| 조건 | `hand_j_kin` | `paxini_ft` | `fruit_pos` | `fruit_quat` | `fruit_size` |
|---|---:|---:|---:|---:|---:|
| 정상→정상 | +0.032 | +0.014 | +0.006 | +0.002 | +0.002 |
| **낙하→낙하** | **+0.059** | **+0.051** | **+0.053** | **+0.054** | **+0.030** |
| 정상→낙하 (전이) | 손만 R² **−0.046** | | | | |

과일 방향 **27배**, 과일 위치 8.6배, paxini 3.6배. 그리고 정상 데이터로 학습해 낙하
구간에 적용하면 R² 가 −0.046 으로 무너진다 — **레몬이 떨어지려는 바로 그 순간에
정책이 가장 못한다.**

### 결론

센서가 쓸모없는 게 아니라, **쓸모 있는 구간(미끄러짐·회복)을 학습셋에서 빼버렸다.**
정상 회전만 24개 모으면 손 관절이 액션을 거의 결정하므로, 어떤 아키텍처를 써도
촉각·과일은 무시된다. 아키텍처(모달리티 분리·손가락 토큰·DiT)나 증강(dropout)으로는
못 고친다.

## 5. 다음 수 (효과 큰 순서)

1. **미끄러짐·회복 데이터 수집.** 파지를 일부러 풀어 레몬이 5~10mm 눈에 보이게
   흘러내리게 한 뒤 재파지 — 에피소드당 5~6회, 5 에피소드면 25~30 이벤트.
   이게 촉각·과일이 액션을 바꾸는 유일한 구간이다.
2. **낙하 에피소드를 통째로 버리지 말 것.** 떨어지기 직전까지의 구간이 바로
   미끄러짐 구간이다. "낙하 시점 인덱스"를 노트에 적어 주면 그 앞까지만 쓸 수 있다
   (`CLAMP_SPEC` 에 숫자로 넣으면 된다 — 8/5 노트 형식 그대로).
3. **중지 F/T 수리** — 12채널 중 3채널이 0이면 촉각 정보의 1/4 이 비어 있다.
4. 그 다음에야 아키텍처를 비교할 가치가 생긴다. 지금은 `13_v2_split` 과
   `12_v2_baseline` 의 차이(−1.4%)가 홀드아웃 3 데모의 노이즈에 묻힌다.

## 6. 재현

```bash
cd diffusion_policy
python3 train.py --mode preflight                      # 클램프 표·shape·NaN·ETA
./launch_train.sh runs/v2_base 400 --lr 3e-4 --val_action_every 10
python3 eval_rollout.py  --ckpt runs/v2_base/best.pt   # rollout + 플롯
python3 copy_baseline.py --ckpt runs/v2_base/best.pt   # 복사 기준선
python3 ablate.py        --ckpt runs/v2_base/best.pt   # 센서군 기여도
python3 probe.py         --ckpt runs/v2_base/best.pt   # 선형 프로브
python3 probe_drop.py                                  # 낙하 구간 프로브

cd ../vtdp_wrapper                                     # 원본 레포 아닌 복사본
python3 train.py --config configs/12_v2_baseline.yaml --mode full \
    --override train.batch_size=256 --out_dir runs/12_v2_baseline
python3 train.py --config configs/13_v2_split.yaml    --mode full \
    --override train.batch_size=256 --out_dir runs/13_v2_split
```

wrapper 복사본에 가한 변경은 2가지뿐이다 (원본 레포는 손대지 않았다):
`vtdp/data.py` 의 `KEY_DIMS` 에 신규 스키마 키 추가, config 2개 신설.
